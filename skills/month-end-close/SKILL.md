# 月末结账规程

## 何时使用

用户说"结账""关账""把这个月封了"，或定时任务触发月度结账时。

**结账是全系统唯一不可逆的动作**：结完这个期间的账不能再改，
只能通过下期调整。所以下面五步一步都不能跳，顺序也不能换。

## 步骤

1. **确认期间没有被结过**。先调 `list_closed_periods`。
   已结过的期间再结一次会被拒绝——但你要先知道，而不是靠报错才发现。

2. **清空待审核队列**。调 `list_pending`。
   有未审核单据时结账会被拒绝，因为那些单据本该记在本期。
   逐笔判断该记什么科目，然后**提交审核**——注意 `post_voucher` 需要人工审批，
   你不能替会计签字；把单据整理好、给出建议科目，等人在界面上批。

3. **跑一次月度对账**。调 `reconcile_month`，看返回的 `anomalies`。
   三类异常必须逐条解释或挂起：
   - **大额支出**：为什么这笔比同类大一个量级？
   - **疑似重复记账**：同一金额 + 同一摘要 + 同一单据出现多次，往往是重复提交
   - **缺凭证**：没有附件的单据不能进报表

   结账前还要做一次**全面稽核**：用 `spawn_teammate` 招常驻稽核员（`auditor_wang`），
   再 `assign_task` 让它核本期间全部账目，拿到回报再往下走。
   日常单笔核对才用 `task` 派子 Agent——一次性委派记不住上一轮查过什么，
   而月末稽核要反复查、跨轮次对照。招人要人工审批，这是正常流程；
   稽核完用 `shutdown_teammate` 让它下班。

4. **核对当期收支合计**。把 `reconcile_month` 的 `income` / `expense`
   与 `query_entries` 按日期区间查出来的结果对一遍，两个数必须一致。
   不一致说明有账目落在区间边界之外，先查清楚再结。

5. **执行结账**。调 `close_period`。它会把这期损益结转到「本年利润」并封存期间。

## 报告要求

结账结论里必须写明：**期间、笔数、当期收入、当期支出、净额、异常条数**。
这些数字全部来自工具返回，不要自己算，更不要估。

## 禁止

- 不要在待审核队列非空时强行结账——被拒绝是设计，不是故障。
- 不要在异常未解释的情况下结账并说"已清理"。异常要么解决，要么明确挂起。
- 不要用 `generate_report` 的输出代替结账。出报表只是展示，封存期间才是结账。
