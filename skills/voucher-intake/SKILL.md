# 出纳收单规程

## 何时使用

用户上传发票/收据/回单，说"帮我记账""这笔记一下"时。

## 两条硬约束

这两条是**代码级的**，不是靠自觉——违反了工具会直接拒绝，返回 error。
遇到 error 不要重试，先看下面哪一条没过。

### 约束一：没有凭证文件就不能记账

`submit_voucher` 会检查 `data/attachments/` 下是否真有这个文件。
用户只在聊天里描述了"买了台电脑"但没有附件 → 不能记账。

**该怎么回应**：说明"记账必须有发票或收据作为凭证"，并请用户上传。
不要为了"把事办成"而编造一个凭证文件名。

### 约束二：出纳不定科目

`submit_voucher` 只登记"钱动了"这个事实，**不生成借贷分录**，`category` 留空。
科目是会计审核时（`post_voucher`）才定的。

这不是实现偷懒，是内控：出纳既管钱又管账，挪用了公款自己改账就没人发现。

## 步骤

1. **确认凭证**。文件名来自系统注入的提示（用户本次上传的文件名），照抄即可，不要自己编。

2. **判断收付方向**（`entry_type`）：
   - `expense` 付钱出去（买办公用品、付房租）
   - `income` 收钱进来（客户回款）
   - `asset` 资产内部转换（买设备——钱变成固定资产，不进当期损益）

3. **登记**。调 `submit_voucher`，附上 `amount` / `description` / `voucher` /
   `entry_type`，有对方单位就填 `counterparty_name`。

4. **告诉用户下一步**。登记后状态是 `pending`（待审核），**不进报表**。
   回复里要说明"需会计审核后才计入报表"，并提示去「📚 智能会计」页面审核。

## 禁止

- 不要把"待审核"说成"已记账"。这两件事在财务上是不同的法律状态。
- 不要在金额不确定时猜一个数填进去。金额来自凭证，不是来自推测。
- 不要试图用 `post_voucher` 直接入账来"加快流程"——它会阻塞等人批。
